## 2. Teams 봇 핸들러와 턴 흐름

**봇(`src/bot/main.py`)**
- `handle_conversation_update`(284행): 사용자가 **1:1 개인 채팅**에 추가될 때만 `kind="welcome"` 턴을 보낸다.
- `handle_message`(301행): 메시지와 카드 버튼 값(`activity.value`)을 `/api/turn`으로 중계한다. 카드 버튼은 모두 `Action.Submit`이고 값은 메시지 활동으로 온다(Playground에서 `Action.Execute` 클릭이 안 나가는 문제의 우회).
- `on_card_action_execute` 3개(`menu`, `claim_issue`, `dismiss_claim_card`)는 실제 Teams용으로 남겨 둔 경로다.
- `relay`(215행): 서버가 보내는 NDJSON 이벤트 `status` / `chunk` / `message` / `buttons` / `ping` / `done`을 Teams 스트림·메시지·카드로 옮긴다. 150초 넘게 열려 있으면 실패 안내를 보낸다.
- Adaptive Card 종류는 코드에 **네 가지**뿐이다(`_build_buttons_card`, 169행): ① 글+버튼(기본) ② `_stepper_card` 제목·글·서버가 그린 PNG(단계 표시줄)·버튼 ③ `_choice_card` 드롭다운 1개+버튼(`input_id`로 값 이름 지정) ④ `_form_card` 텍스트·토글·선택 입력+버튼. `TextInput`은 `style="Text"`로 고정이라 **비밀번호 입력 카드가 없다**. 카드를 **제자리에서 갱신**하는 경로도 없다(항상 새 메시지).
- 그 밖에: 탭 화면·API·단계 이미지를 서버로 넘기는 프록시(`/tab/board`, `/api/board*`, `/img/stage.png`).

**서버(`src/server/main.py`)**
- `/api/turn`(193행): 시크릿 검사 → `Turn` 만들기 → `handle_turn`을 별도 작업으로 100초 제한으로 실행 → 큐의 이벤트를 NDJSON으로 흘림(15초마다 ping).
- `Turn.team_key`(164행): 팀 채널이면 `team:<팀ID>`, **1:1 채팅이면 `user:<aad_id>`**. 설정·저장소 범위가 모두 이 값이다.
- `handle_turn`(462행) 순서: welcome이면 `_send_welcome` → 설정이 있으면 팀원 기록(`_sync_member`)과 Notion 변경 확인(`_check_on_open`, 10분마다) → 카드 값(`_dispatch_value`) → 텍스트(`_handle_text`).
- `_handle_text`(553행)의 분기 우선순위: 처음 등록(역할) 세션 → 회의록 [고치기] 세션 → 취소어 → 소스 추가 → 회의록 올리기 → 설정 마법사 → GitHub 아이디 묻기 → 질문하기 세션 → 조율 세션 → `설정`/`0` → `별칭` → `권한` → `1`~`4` → 인사 → 그 밖은 "올바른 값을 입력하세요. (1~4, 연결 설정 변경은 '설정')".
- **자유 채팅 이해는 없다.** 자연어는 `💬 질문하기` 세션 안에서만 LLM으로 처리한다.
- 세션은 모두 **서버 메모리**(`setup_sessions`, `github_onboarding_sessions`, `qa_sessions`, `member_flow.sessions`, `confirm_flow.upload_sessions` 등)라 서버를 다시 켜면 사라진다.

## 3. 현행 메뉴 구성

**메인 카드**(`_send_welcome`, 2249행): ① 설정이 있으면 `🔔 알림` 카드(확인 대기 회의록, 자동 반영, 삭제 확인, 정리 중, 관리자용 멈춘 처리 수, 최대 5줄) ② 단계(stage) 카드 ③ 메뉴 카드(`WELCOME_TEXT` + 버튼). 설정이 없으면 ③에 번호 메뉴 4개만 보인다.

| 버튼(현행) | 동작 |
| --- | --- |
| 1️⃣ 팀/프로젝트 정보 | `fetch_project_info`: 산출물 문서 요약+팀 정보로 프로젝트 설명(문단마다 출처). 문서가 없으면 팀 정보 페이지 요약. |
| 2️⃣ 진행상황 조회 | `fetch_team_status`: 결정됨/진행 중/불명확 브리핑+GitHub 상태, 안건, 보류 항목. 아래에 `질문하기`·`조율 보기`·`구조 보기` 버튼. |
| 3️⃣ 내 역할 조회 | `fetch_my_role`: 내게 배정된 GitHub 이슈+회의록에서 맡은 일, 담당 없는 할 일 중 내 역할에 맞는 것 [내가 맡기]. |
| 4️⃣ 작업 공유·회의록 반영 | 하위 메뉴(`confirm_flow.SUBMENU`): 완료한 작업 공유 / 작업물 공유하기 / Notion 변경 반영 / 최근 반영 내역 / 회의록 올리기 / 소스 추가. |
| 💬 질문하기 | 질문 세션 10분. 저장된 지식 검색+(필요하면) GitHub → 답 카드·안건 버튼. |
| 🗂 구조 보기·고치기 | 서명 링크로 Teams 탭(지식 대시보드)을 연다. |
| (입력) `설정` / `0` | 설정 마법사 시작. 이미 설정된 팀은 **처음 등록한 관리자만** 다시 할 수 있다. |
| (입력) `별칭`, `권한` | 별칭 고치기, 관리자의 권한 카드. |

**설정 마법사(현행, 채팅 텍스트 6단계)**: `SETUP_STEPS`(397행) = ① GitHub 레포 ② GitHub 토큰 ③ 본인 GitHub 아이디 ④ Notion 토큰 ⑤ 팀 정보 Notion 페이지 링크 ⑥ GitHub 프로젝트 번호. 회의록 페이지는 묻지 않는다(팀 정보 페이지 안에서 판정; 예전에 저장된 값은 계속 읽음). 입력마다 검증한다: 토큰은 GitHub API로 실제 인증(`_github_token_valid`), Notion 페이지는 실제 조회(`_notion_page_accessible`), Notion 토큰이 GitHub 토큰과 같으면 거부. `가이드`라고 보내면 토큰 발급 안내(`_SETUP_GUIDES`). `취소`/`나가기`로 중단. 끝나면 요약 글 "✅ 설정 완료"를 보내고 `team_configs.json`에 저장하며 입력한 사람을 관리자로 기록한다. 페이지를 등록한 순간 백그라운드로 구조·원문을 읽어 저장한다(`_register_team_map`).

**처음 등록(팀원, `member_flow`)**: 설정이 있는 팀에서 역할이 없는 사람이 처음 말을 걸면 역할 버튼(기획/디자인/개발/기타) → GitHub 아이디(건너뛰기 가능) → 별칭(건너뛰기 가능). 역할은 건너뛸 수 없다.

**권한**(`people.can_approve`): 관리자이거나, 역할이 `dev`이거나, 관리자가 준 사람이 승인·되돌리기·삭제 확인을 한다. 탭 고치기도 같은 기준이다.

## 4. HTML 시안의 화면·상태 목록

HTML은 Teams 채팅 창을 흉내 낸 단일 파일이고, 위쪽 스위치로 시나리오 A/B를 바꾼다. 상태는 모두 메모리 변수(`scenario`, `setupStep`, `guideOpen`, `setupData`, `verified`, `stepError`, `myRole`, `teamRegistered`)이며 서버·저장 없음(검증은 시뮬레이션).

**공통**
- C-01 레이아웃: 좌측 레일·사이드바(채팅/활동/팀/앱 "대시보드"), 상단 "SEAM PM Bot", 타임라인, 하단 입력창과 안내문("채팅을 기본으로 사용하며, 입력·선택·승인 등 필요한 경우에만 작업 UI를 제공합니다.").
- C-02 시나리오 전환(A 등록된 팀 없음 / B 등록된 팀 있음): 시안 전용.
- C-03 메뉴 카드 "SEAM 시작하기"(설명 "필요한 기능을 선택하거나 채팅으로 요청하세요."): 버튼 **팀 현황 / 업무 확인 / PM Bot 질문 / 설정**. 하단 도움말 줄: 팀 등록 전 "팀 등록이 필요합니다. [초기 설정 시작 →]", 등록 후 "개인 정보와 팀 공통 설정은 별도로 관리합니다. [내 정보] [팀 설정]".
- C-04 퀵 액션: 버튼을 누르면 사용자 말풍선이 생기고 같은 문장이 채팅으로 처리된다(예: "팀 현황 알려줘").
- C-05 자유 채팅 응답 규칙(키워드): `설정`/`초기 설정`, `내 정보`, `팀 설정`, `팀 현황`·`진행 상황`·`업무 확인`·`담당자`·`지연`, `회의`, `질문`, 그 밖(안내 말풍선).
- C-06 업무 표 카드: "담당자별 업무" / "일정 확인 필요 업무"(업무·담당자·상태 표, [상세 내용 확인]).
- C-07 토스트(시뮬레이션 알림).

- A-09 확인 완료 상태: "✓ 연결 정보 확인 완료" + [다음 단계] + [← 이전 단계]; 토큰 형식 규칙 `ntn_`·`secret_`.
- A-10 **3/3 팀 정보 확인 및 확정 카드**: 태그 "Notion 추출 결과 · 시뮬레이션", 확인된 정보(프로젝트명·목표·기간·팀 정보 페이지·회의록 페이지), 확인 상태 세 줄(✓ 확인됨 / 미설정 / 추가 확인), `확인 의견 (선택)` 입력, [팀 정보 확정].
- A-11 **설정 완료 카드**: GitHub 연결됨, Notion 연결됨, 팀 정보 "Notion 추출 결과 확정", 미설정 n건, 추가 확인 n건, [팀 설정에서 보완하기 →]. 이어서 메뉴 카드 다시 표시.

## 7. 테스트 실행 결과

**실행 방법(외부 HTTP 차단 확인 후)**
1. 저장소는 건드리지 않고, 작업 트리의 **소스 파일만**(추적 파일+추적 안 된 새 소스, `.sqlite3`·`.env*`·`team_configs.json`·`member_profiles.json`·실제 Notion 녹화 폴더 제외, 94개)을 임시 폴더에 복사해 거기서 실행했다. 실제 설정·DB·키를 테스트가 읽거나 쓸 경로가 없다.
2. `tests/isolation.py`는 임시 저장소·LLM 키 비우기·보호 저장소 차단만 하고 **외부 HTTP는 막지 않는다**. 그래서 별도 실행기(임시 폴더 `guard_run.py`)로 `socket.connect`·`create_connection`·DNS·asyncio `create_connection`/`sock_connect`(Windows Proactor 포함)를 막고 루프백만 허용했다. 실행 전 자체 점검: 공용 IP 소켓, 호스트명 연결, DNS, httpx 동기 GET(Notion 형태), httpx 비동기 GET(GitHub 형태), asyncio 연결 **6경로 모두 차단됨**, 루프백 정상.
3. 첫 실행은 복사 누락(추적 안 된 `worklog/github.py`)으로 import 오류 20건이 났고, 복사를 고쳐 **다시 실행**했다(아래가 최종 결과).

**결과**: 390개 실행, **실패 0, 오류 0, 건너뜀 2**. 건너뜀 2건은 실제 Notion 녹화본이 있어야 하는 `test_fixtures`·`test_parts`의 테스트로, 녹화본 폴더를 일부러 복사하지 않아 건너뛰었다.

**차단된 외부 연결 시도 2건**(호스트 이름만 기록): `create_connection:api.notion.com` × 2. 테스트가 가짜 Notion 자격증명으로 Notion에 나가려 한 흔적이며(PRD §10.2의 알려진 기술 부채와 같은 현상), 차단되어 실제 요청은 나가지 않았다. 어느 테스트인지는 추적하지 않았다.

**실행 전후 확인**: 실제 `src/team_configs.json`·`member_profiles.json`·`worklog.sqlite3`의 수정 시각과 작업 트리 상태가 실행 전후로 같았다(복사본에서 실행했으므로 당연하지만 확인함). 커밋·설정 변경 없음.

참고: 작업 트리의 최근 전체 실행 기록(Phase 4 시점 314개 통과)과 개수가 다른 것은 이후 Phase 5~7 테스트가 추가됐기 때문이다.

## 8. HTML대로 바꿀 때의 위험

**데이터 모델**
1. **팀 범위(`team_key`)**: 현행은 팀 채널이면 `team:<ID>`, 1:1 채팅이면 `user:<aad_id>`이고 welcome은 1:1에서만 나간다. 시안 B("팀 정보는 이미 등록되어 있어요")는 팀원이 자기 1:1 채팅에서 **팀 공용 등록**을 본다고 전제한다. 현행에서는 1:1 채팅 사용자마다 설정·저장소 범위가 따로라서 이 전제가 성립하지 않는다. 가장 큰 불확실성이다.
2. **역할 분류**: `people.ROLES`는 4종(`plan/design/dev/other`)이고 권한(`dev`=승인자)·할 일 `role_hint`·3번 메뉴 [내가 맡기]가 이 값에 걸려 있다. 시안의 6종+직접 입력(프론트엔드·백엔드·데이터·AI)을 넣으면 권한 규칙과 기존 `members.role` 값·기존 할 일의 `role_hint` 매핑을 정해야 한다. 직접 입력한 문자열을 어디에 저장할지도 정해져 있지 않다.
3. **팀 정보 확정 단계(A-10)**: 프로젝트명·목표·기간 추출, "확인됨/미설정/추가 확인" 상태, 확인 의견은 현재 저장 위치(`team_configs.json` 키, DB 테이블)와 LLM 지침이 모두 없다. 새 데이터와 새 LLM 호출이 필요하다.
4. **프로젝트 번호**: 현행 설정 6번째 값(`github_project_number`)을 4번 ① 완료 공유가 GraphQL로 GitHub Project 상태를 바꾸는 데 쓴다. 시안에는 없고 시안의 "업무 관리"는 Notion 프로젝트 페이지다. 그대로 빼면 완료 공유의 Project 동기화가 끊긴다. 시안의 개념으로 바꾸면 업무 관리 소스 자체가 달라진다.
5. **기존 설정 호환**: 저장된 설정 키(`github_repo`, `github_token`, `notion_token`, `notion_page_id`, `github_project_number`, `admin_aad_id`, `extra_source_ids`, `meeting_notes_page_id`, `notes_found_noticed` 등)와 `members`·`team_members` 표가 이미 쓰이고 있다. 시안 필드를 추가하려면 이 JSON과 DB에 호환되게 넣어야 한다.

**권한**
6. 설정 변경은 `admin_aad_id`(처음 등록한 사람)로 고정이다. 시안 B의 "팀 설정"은 조회 전용이고 `내 정보`는 누구나 바꿀 수 있어 보이는데, 현행에서는 역할 고치기가 관리자 영역이다(`권한` 카드). 누가 무엇을 바꿀 수 있는지 정의가 다르다.
7. 승인·탭 고치기가 `people.can_approve` 하나에 의존한다. 역할 체계를 바꾸면 이 판정이 같이 바뀐다.

**토큰·비밀 저장**
8. 토큰은 **채팅 메시지로 받고**(대화 기록에 평문으로 남음) `src/team_configs.json`에 **평문 JSON**으로 저장된다(`.gitignore`로 커밋만 제외). 시안은 비밀번호 입력란이지만 현행 카드 코드는 `style="Text"` 고정이라 비밀번호 입력 카드가 없다(Teams의 비밀번호 입력 지원 여부는 [미확인]). 암호화·시크릿 저장소 도입은 현재 범위에 없다. 루트에 오래된 `team_configs.json`·`member_profiles.json` 사본이 남아 있어(코드는 읽지 않음) 정리 대상이다.
9. 설정 단계마다 GitHub·Notion에 **실제 요청**을 보낸다(토큰 인증, 페이지 조회). 시안의 시뮬레이션 검증과 달리 실패 원인(권한·네트워크)이 다양하다. 테스트 기반이 외부 HTTP를 막지 않는 점도 같은 위험이다.

**상호작용·구조**
10. 시안은 같은 카드가 **제자리에서 바뀐다**(단계 이동, 가이드 토글, 오류 표시). 봇은 항상 새 메시지를 보내고 카드 갱신 경로가 없다. Teams의 카드 갱신(`Action.Execute`·활동 업데이트)을 쓰면 되지만, 현재 Playground에서 `Action.Execute` 클릭이 나가지 않는 우회가 코드에 남아 있다(`bot/main.py` 47행 주석·`Submit` 사용).
11. 단계 입력 상태(`setup_sessions`)가 서버 메모리라 재시작하면 진행 중이던 설정이 사라진다. 다중 필드 카드로 바꾸면 사용자별 임시 저장 위치가 필요하다.
12. 시안의 "채팅이 기본" 원칙과 현행의 "번호 메뉴가 기본" 원칙이 부딪친다. 자유 문장 이해(C-05)를 넣으면 LLM 호출(무료 한도, 사용자 대기 순위)과 오인식 처리 규칙이 새로 필요하다.
13. 문구 체계가 다르다: 시안은 "~합니다/입니다"가 많고 현행은 "~해요" 체다. 현행 테스트는 한국어 문구를 그대로 비교하는 곳이 많아 문구를 바꾸면 테스트가 같이 깨진다.
14. 작업 트리에 커밋되지 않은 Phase 5~7 변경이 있어 "기준선"이 흔들릴 수 있다.
