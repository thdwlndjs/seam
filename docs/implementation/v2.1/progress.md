### 2026-11-06 실데이터 복사본·실제 LLM 최종 검증

- 기존 실데이터 복사본에서 별도 임시 DB를 만들고 실제 설정의 Groq·Cerebras LLM을 호출했다. 원문은 저장소·진행 기록에 옮기지 않았다. 조율 입력은 22개 항목이었으나 작업은 1개, 저장 관계는 0개, 역할이 기록된 팀원은 1명이어서 실제 역할 의존성·병렬성 검증 범위가 제한됐다.
- 메뉴 경로는 유효 응답 기준 1회 호출로 네 구역을 생성했다. 한 차례는 `CoordinationResult` 필수 키 누락으로 거부됐다. 유효 응답도 근거 없는 2일 일정·작업 선후관계·병렬 가능성 및 데이터 소스 작업을 제안했다. 역할 간 조율 설명에 등장한 역할과 구조화된 역할 필드가 일치하지 않았다. 입력 관계가 없는데도 모델이 의존성을 단정했고, 선택하지 않은 Spike 방법을 RAID 근거에 섞었다.
- 대안 질문은 표현에 따라 QA만 1회 호출하고 조율로 분기하지 않은 경우가 있었다. 명세 대표 문구를 포함한 질문에서는 QA 1회+조율 1회로 총 2회, 두 공급자에 걸쳐 종료했다. 그러나 출력은 요청한 “구현하면서 QA 병행” 대안을 그대로 비교하지 않고, 기록 부재를 “현재 QA 없음”으로 단정했으며 Product Discovery·Spike를 QA 프레임워크처럼 제시했다. 프로젝트 근거와 일반적 추정을 구분하지 않은 위험·효과 설명도 포함됐다.
- 두 조율 입력의 공급자 실제 prompt token은 6,211·6,257로, 코드 추정 예산 5,000을 초과했다. 응답 계약 검사는 알 수 없는 ID·필수 키를 막지만 문장과 근거의 함의 관계, 자유 서술 역할, 입력에 없는 일정·인과를 막지 못했다.
- 검증 도중 호출량 계측 경로가 임시 사본이 아닌 `src/worklog.sqlite3`를 가리켜 Groq 9,283토큰 단일 행을 잠시 기록했다. 검증 종료 후 해당 행만 조건 확인 후 제거했고 재조회에서 행 부재와 스키마 버전 9를 확인했다. 후속 LLM 호출은 import 전에 임시 사본 경로를 설정했다. 임시 사본은 정리했다.
- 회귀 보완: 계측 경로가 import 뒤 `WORKLOG_STORE` 변경을 반영한다. 테스트 모드에서는 보호 대상 DB 경로를 `db.connect`가 파일 생성·WAL 설정 전에 차단한다. 모의 LLM 호출에서 import 뒤 경로 변경을 재현한 회귀를 먼저 실패시킨 뒤 통과시켰다. 표적 격리 테스트 4개와 HTTP 차단 전체 회귀 372개(124.341초)가 통과했다.
- 계측 잔여 확인: 이전에 잘못 기록된 Groq 9,283토큰 행은 현재 없고 스키마 버전은 9다. 회귀 중 테스트 경로가 보호 대상 DB를 열면 파일 생성 전에 거부됨을 확인했다. 애플리케이션의 기존 사용량 계측은 계속 설정된 운영 저장소를 사용한다. 복사본 검증 도구는 경로를 모듈 import 전에 지정하거나 명시적으로 격리해야 한다.
- 실모델에서 얻은 오류 사례는 Phase 6 기능 완료와 분리해 A/B 평가 기준선으로 보존한다. 이번 작업에서는 기존 AI 호출 구조·프롬프트·조율 동작을 변경하지 않았다. 전체 회귀 372개 통과는 DB·코드 동작 회귀 결과이며 의미 정확도 평가 결과가 아니다. 실제 Teams 화면·카드 버튼 및 링크 이동은 별도 확인이 필요하다.

후속 작업: 확보한 실모델 오류 사례를 포함해 의미 정확도 A/B 평가를 설계·실행하고, 공급자 실측을 바탕으로 토큰 예산을 보정한다. 이번 Phase 6 완료에는 포함하지 않는다. 실제 Teams UI 항목은 별도 수동 검증한다. Phase 5 기존 20문항의 사람 판정·미해결 오류와 정합성 B는 후속 과제로 유지한다. 실행 중 서버의 최신 코드 반영 여부는 미확인이다.
