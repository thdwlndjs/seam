# 01 · setup: 초기 설정, 팀·개인 등록

상태: 로직 확인까지 끝남(테스트·검증 도구). 실제 Teams 화면 확인은 아직 하지 않음 · 브랜치 `seam/01-setup`

## 1. 목적과 범위

팀에서 처음 봇을 연 사람이 노션만 연결하면 팀 전체가 바로 쓸 수 있게 한다. 누가 어느 팀인지는 사람에게 묻지 않고 명단으로 정한다.

| 바꾸는 것 | 안 바꾸는 것 |
| --- | --- |
| 시나리오 A: 연결 전인 팀에 처음 온 팀원의 팀 연결 카드 흐름 | 시나리오 B: 연결된 팀의 팀원 등록(역할 → GitHub 아이디 → 별칭) |
| 명단 밖 사람에게 보이는 안내(어느 팀에도 연결하지 않음) | 메뉴 4개와 그 안의 기능 |
| GitHub 없이 연결한 팀에서도 메뉴가 오류 없이 동작 | 예전 범위의 팀 데이터(`user:…`, `team:…`)와 그 설정 |
| 개발용 번호 대체(Playground 확인용) | 명단을 넣지 않은 설치의 동작(예전 방식 그대로) |

## 2. 화면 흐름: 시안 ↔ 구현

시안: [ui-mockup-v2.html](ui-mockup-v2.html)의 "팀 초기 설정" 카드(`steps`: github → notion → review)와 완료 카드.

| 순서 | 시안 화면 | 구현 카드(제목) | 서버 동작 |
| --- | --- | --- | --- |
| 0 | 안내 말풍선 "아직 등록된 팀 정보가 없습니다" | `○○팀이시네요 👋` [팀 연결 시작하기] | 명단으로 팀을 찾고, 그 팀이 연결 전이면 이 카드를 보인다 |
| 1 | Notion 연결(토큰, 팀 정보 페이지 링크) | `1 / 2 · 노션` 「팀 노션 페이지를 알려 주세요」 (링크 + 토큰 가림 입력) | 형식 검사 → 실제 페이지 열기. 통과하면 제출 카드를 값 없는 카드로 바꾸고 **바로 팀 연결을 저장** |
| — | 팀 정보 확인 및 확정(프로젝트명·목표·기간) | **없음(뺐음)** | 결정 기록 D-3 |
| 2 | GitHub 연결(저장소, 토큰) | `2 / 2 · GitHub (선택)` → 「팀 저장소를 알려 주세요」 | [나중에 할게요]로 건너뛸 수 있다. 토큰 로그인 → 저장소 열기 확인 |
| 3 | (시안에 없음) | 「작업 보드가 없네요」 [만들어 주세요] / [괜찮아요] | 저장소에 열린 보드가 있으면 그걸 연결하고, 없으면 물어본 뒤 만든다 |
| 4 | 완료 카드(GitHub·Notion 연결됨) | 「준비 끝! 🎉」 | 연결된 것과 나중에 할 것을 보인다 |

시안과 다른 점:
- **순서.** 시안은 GitHub를 먼저 묻지만, 구현은 노션 → GitHub(선택) 순서다. "노션 필수, GitHub 선택"(D6)으로 합의한 토스식 시안(카드 하나에 질문 하나)을 따랐다.
- **빠진 입력칸.** 시안의 "관리자 GitHub ID", "회의록 페이지 링크(선택)" 칸은 이 흐름에 넣지 않았다. 관리자는 연결한 사람이 되고, GitHub 아이디는 시나리오 B 개인 등록에서 받는다.
- **완료 카드.** 시안의 "미설정 1건 · 추가 확인 1건 (예시)" 줄은 넣지 않았다. 채울 실제 값이 없기 때문이다.

명단 밖 사람: 어떤 입력을 하든 「어느 팀인지 찾지 못했어요 …」 한 가지 안내만 받는다. 이름과 번호는 되풀이하지 않는다.

## 3. 완료 기준과 결과

증거 폴더는 `docs/refactor/evidence/`이고, 커밋하는 것은 `steps.json`과 `check.json`이다. 화면 캡처(PNG·HTML)는 같은 명령으로 다시 만든다(§7).

| 완료 기준 | 결과 | 증거 |
| --- | --- | --- |
| 1. 명단 팀원이 팀 인사 → 노션 → GitHub(선택) → 보드 → 완료 순서로 지나간다. 지어낸 번호로 확인한다 | 로직 통과 · Teams 미확인 | `after-A/`, `test_first_member_connects_notion_and_skips_github` |
| 2. 노션은 실제 접근 확인을 통과해야 하고, GitHub는 [나중에]로 건너뛸 수 있으며, GitHub 없이도 메뉴가 동작한다 | 로직 통과 · Teams 미확인 | `after-A/` 3단계(틀린 토큰은 막힘), `after-A-no-github/`, `test_menus_work_without_github` |
| 3. 같은 팀 두 번째 팀원은 역할 선택(B)으로 간다. 동시에 설정하면 먼저 끝낸 쪽만 저장된다. 명단 밖 사람은 어느 팀에도 연결되지 않는다 | 로직 통과 · Teams 미확인 | `after-B/`, `after-blocked/`, `ConcurrentSetupTests` |
| 4. 토큰·번호가 채팅·로그·커밋에 남지 않는다. 기존 팀 데이터는 그대로다. 네트워크를 막은 전체 테스트가 통과한다 | 로직 통과 | `LeakTests`, `test_existing_team_data_is_never_changed`, 전체 테스트(커밋 메시지에 결과) |

시나리오 B를 변경 전(`before-B/`)과 비교하면 별칭 질문의 예시 한 줄만 달라졌다. `(예: User 902, …)`가 `(예: 줄인 이름이나 영어 이름)`으로 바뀌었다. 표시 이름의 번호가 채팅에 남지 않게 하려는 변경이다.

## 4. 데이터 설계

**마이그레이션 10(추가만).** 기존 표는 바꾸지 않는다. 같은 DB에 두 번 실행해도 결과가 같다.

| 표 | 칸 | 뜻 |
| --- | --- | --- |
| `teams` | `scope`(PK, `squad:<팀 코드>`), `name`, `status`(new · setting_up · connected), `setup_by`, `setup_started_at`, `connected_at`, `updated_at` | 팀 등록부와 연결 상태 |
| `roster` | `member_no`(PK), `scope`(→ teams), `is_leader` | 번호 → 팀. 이름 칸은 없다 |
| `team_config_log` | `id`, `scope`, `field`, `action`(set · cleared), `actor`, `changed_at` + 색인(`scope`, `changed_at`) | 누가·언제·무엇을 바꿨는지. 값은 남기지 않는다 |

명단은 `python -m worklog roster-load --file <명단.json>`으로 넣는다. 여러 번 넣어도 결과가 같고, 화면에는 개수만 나온다. 다른 팀에 있는 번호를 옮기는 명단이나 `dev-`로 시작하는 팀 코드는 거부하고, 이때는 아무것도 넣지 않는다. 명단 파일(`roster*.json`)은 커밋하지 않는다.

**`src/team_configs.json`(커밋 제외, 평문).** 팀 범위 `squad:<코드>` 아래에 다음 키를 둔다.

| 키 | 언제 |
| --- | --- |
| `notion_token`, `notion_page_id`, `team_name`, `admin_aad_id` | 노션 확인 통과 = 팀 연결 |
| `github_repo`, `github_token` | GitHub 연결(선택) |
| `github_project_id`, `github_project_number` | 작업 보드 연결 또는 만들기 |

이미 값이 있는 키는 덮어쓰지 않는다. 쓸 때는 임시 파일에 쓴 뒤 바꿔 끼우고, 프로세스 잠금을 건다.

## 5. 규칙

- **Always:** 토큰·링크 검사는 카드 제출을 받는 한 곳(`setup_flow._check`)에서만 한다. 토큰 입력은 Adaptive Card 1.5 `Input.Text` `style: Password`로 받고, 제출한 카드는 값 없는 카드로 바꾼다. 같은 제출이 두 번 와도 결과가 같다.
- **Ask first:** 기존 팀 데이터나 설정 값 바꾸기, 명단에서 번호를 다른 팀으로 옮기기, 실제 DB에 마이그레이션·명단 적용.
- **Never:** 토큰·번호를 카드 문구·오류 메시지·로그·커밋·테스트에 남기기. 테스트는 지어낸 번호(90xx)만 쓴다. 기존 `user:`·`team:` 데이터 삭제·덮어쓰기.

## 6. 결정 기록

| # | 결정 | 이유 |
| --- | --- | --- |
| D-1 | 명단에 없는 사람은 막는다(어느 팀에도 연결하지 않고 안내만) | 잘못된 팀에 토큰·회의 내용이 섞이지 않게 한다 |
| D-2 | 개발용 번호 대체: `SEAM_ENV=development`일 때만 `SEAM_DEV_MEMBER_NO`로 Playground 사용자(표시 이름에 번호 없음)를 그 번호로 본다. 번호는 `roster.playground.json`에서만 찾고, 팀 범위는 `squad:dev-<코드>`다. 개발 환경이 아니거나 `CLIENT_ID`·`CLIENT_SECRET`·`TENANT_ID`가 있으면 서버가 시작하지 않는다 | Playground는 사용자 이름을 바꿀 수 없다. 정한 번호는 실제 명단에도 있으므로 실제 팀과 이어지면 안 된다. 번호 값은 로컬 파일과 `.env`에만 두고 문서·커밋에는 쓰지 않는다 |
| D-3 | "이 팀이 맞나요?"(프로젝트·목표·기간) 화면은 뺐다. 노션 확인이 끝나면 바로 GitHub 단계로 간다 | 지금 코드의 노션 요약은 5~10줄 자유 글이라 세 칸으로 나뉘지 않고, 기간을 꺼내는 코드는 없다. 노션 첫 읽기도 약 20초 이상 걸린다(11/3 측정). 빈칸이나 임시 문구는 쓰지 않기로 했다 |
| D-4 | 동시 설정 잠금은 서버 한 대 기준이다. 연결 완료는 DB 잠금(`BEGIN IMMEDIATE`)이라 여러 대여도 한 번만 저장된다. GitHub·보드 단계와 설정 파일 쓰기는 프로세스 안 잠금이다 | 지금 운영은 서버 한 대다. 여러 대로 늘리면 다시 본다 |
| D-5 | 표시 이름에 보이는 번호(`User <번호>`)는 그대로 둔다(권한 카드·탭 이력 등) | Teams가 이미 보여 주는 이름이다. 봇이 새로 만들어 보이는 문구에는 넣지 않는다 |
| D-6 | 토큰은 아직 `team_configs.json`에 평문으로 저장한다. 바꾸는 일은 나중에 한다 | 기업형 연결(GitHub App, Notion OAuth, 배포 서버)과 함께 바꾼다(D8) |
| D-7 | 팀 연결 권한: 지금은 명단 팀원 모두. 처음 시작한 사람이 진행하고, 30분(`TEAM_SETUP_STALE_MINUTES`) 넘게 멈추면 다른 사람이 이어받을 수 있다 | 권한 판단은 한 곳(`teams.begin_setup`·`finish_setup`)에 두어 나중에 팀장 + 개발자 + 승인받은 팀원으로 좁힐 수 있게 한다 |

## 7. 검증 지도

모든 명령은 저장소 루트에서 실행한다. 검증 도구는 임시 DB와 임시 설정만 쓰고, 외부 네트워크를 막는다.

| 화면·흐름 | 들어가는 방법 | 통과의 뜻 |
| --- | --- | --- |
| A 전체 | `.venv/Scripts/python.exe scripts/verify_cards.py A <폴더>` (지어낸 사용자 `User 901`) | 팀 인사 → 노션(틀린 토큰은 막힘) → `2 / 2 · GitHub` → 저장소 → 보드 만들기 → 준비 끝 |
| A, GitHub 건너뜀 | `… verify_cards.py A-no-github <폴더>` | 노션 다음 [나중에] → 준비 끝, 팀 현황 오류 없음 |
| A, Playground 사용자 | `SEAM_ENV=development SEAM_DEV_MEMBER_NO=<개발용 번호> … verify_cards.py A-playground <폴더>` | 「플레이그라운드팀이시네요」. `check.json`에서 `squad:dev-playground`만 connected이고, 같은 번호를 넣은 다른 팀은 new 그대로 |
| B | `… verify_cards.py B <폴더>` (`User 902`, 연결된 알파팀) | 역할 고르기 → GitHub·별칭 건너뛰기 |
| 명단 밖 | `… verify_cards.py blocked <폴더>` (`User 999`) | 어떤 입력에도 「어느 팀인지 찾지 못했어요」 |
| 단위 테스트 | `src/server`에서 `python -m unittest discover -s tests -p test_team_setup.py` | 24개 통과 |

알려진 함정:
- Playground 기본 사용자 `Alex Wilber`는 표시 이름에 번호가 없다. 명단을 쓰면 막히고, 개발용 번호 대체를 켜야 들어간다.
- 개발 서버를 그냥 띄우면 기본 DB(`src/worklog.sqlite3`)에 마이그레이션 10이 적용된다. Playground로 확인할 때는 `WORKLOG_STORE`를 따로 만든 DB 파일로 지정한다.
- 카드 교체(`replyToId`로 제출한 카드를 값 없는 카드로 바꾸기)는 실제 Teams에서 확인하지 않았다. 교체에 실패하면 값 없는 카드를 새 메시지로 보낸다.
- 검증 도구와 테스트의 노션·GitHub 확인은 가짜 함수다. 토큰이 `ntn_ok`·`ghp_ok`로 시작하면 통과한다. 실제 접근 확인은 실제 Teams에서 해야 한다.
- 제출한 카드의 입력값은 Teams 활동 기록에 남을 수 있다(Teams 쪽 동작이라 봇이 지울 수 없다).

## 8. 남은 점

**실제 Teams에서 확인할 것**
1. 노션·GitHub 토큰 칸이 가려져 보이는지.
2. 제출한 카드가 값 없는 카드로 바뀌는지.
3. 실제 노션 페이지·GitHub 저장소 접근 확인이 되는지, 작업 보드가 만들어지는지.
4. 두 번째 팀원이 역할 선택으로 가는지.
5. 명단 밖 계정이 안내만 받는지.

**실제 DB 적용 순서(사람이 Teams에서 확인한 뒤, 따로 승인받고)**
1. `src/worklog.sqlite3` 백업.
2. 새 코드 배포(새 코드와 마이그레이션 10은 함께 나가야 한다. 옛 코드는 DB 판이 더 높으면 시작하지 않는다).
3. 서버 시작 → 마이그레이션 10 적용.
4. `python -m worklog roster-load --file ../roster.json`(서버 폴더에서).
5. 기존 `user:`·`team:` 설정이 그대로인지 확인.
