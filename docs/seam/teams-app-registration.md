# Teams 앱 패키지와 사내 등록 신청

상태: 설계안 · 패키지 생성 및 등록 신청 전

## 목적과 범위

현재 Teams 앱 패키지를 실제 사내 Teams에서 설치 가능한 상태로 정리하고, 조직 앱 카탈로그 등록을 위한 관리자 승인 신청까지 준비한다.

포함:
- 기존 `appPackage/manifest.json`, 아이콘, ZIP 패키지의 내용 확인 및 정리
- 매니페스트가 가리키는 앱 ID와 기존 봇 등록 정보의 일치 확인
- 실제 서비스 주소와 정책 URL 반영 후 ZIP 재생성
- 사내 앱 카탈로그에 관리자 승인을 요청하는 절차

제외:
- 저장소 폴더 구조 재배치
- 봇·서버 코드 변경, DB·팀 데이터 변경
- 새 Entra 애플리케이션 또는 Bot 리소스 생성
- Microsoft Teams Store(AppSource) 공개 게시
- 실제 테넌트 업로드·등록 신청(이 문서 승인 및 필요한 값 확인 전)

## 현재 상태 확인

| 항목 | 현재 확인 결과 | 계획상 처리 |
| --- | --- | --- |
| `appPackage/manifest.json` | 존재. manifest schema 1.17, 버전 1.0.0 | 현재 기능을 기준으로 필드와 지원 스키마를 점검 |
| `color.png`, `outline.png` | 각각 192×192, 32×32 | 재사용 여부 확인. 아이콘 내용은 시각 검토 |
| `teams-app-package.zip` | `manifest.json`, `color.png`, `outline.png`가 ZIP 루트에 있음 | 현재 매니페스트와 ZIP 내부 매니페스트가 다르므로 재생성 |
| 앱 주소 | `example.com`, `your-domain.example.com` 예시 주소가 포함됨 | 실제 HTTPS 도메인과 접근 가능한 URL을 받아 반영 |
| 앱 ID | 매니페스트의 `id`와 봇의 `botId`가 동일한 GUID | 기존 Entra/Bot 등록의 실제 App ID와 일치하는지 확인. 새 ID를 임의 생성하지 않음 |
| 배포 범위 | `personal`, `team`, `groupChat`, 정적 탭 1개가 선언됨 | 현행 제품 범위와 필요한 권한만 확인하고 유지 여부 결정 |

## 신청 경로

이 안은 **조직 내부 사용자용 Teams 사용자 지정 앱을 조직 카탈로그에 올리기 위해 관리자 승인을 신청**하는 경로를 대상으로 한다. Microsoft 문서상 개발자가 앱을 제출하면 Teams 관리 센터의 앱 관리 화면에서 관리자가 검토·승인할 수 있다. 관리자 직접 업로드는 승인 신청과 다른 경로다.

1. 등록에 필요한 실제 앱·도메인 정보를 확인한다.
2. 매니페스트를 확정하고 Teams 공개 스키마 기준으로 검증한다.
3. 매니페스트와 아이콘만 ZIP 루트에 둔 설치 패키지를 다시 만든다.
4. Teams 클라이언트의 사용자 지정 앱 제출 흐름으로 승인 요청을 제출한다.
5. Teams 관리 센터에서 요청이 접수되어 검토 대기 상태인지 확인한다.
6. 승인 여부는 관리자가 결정한다. 신청 접수와 게시 완료를 구분해 보고한다.

참고: [사용자 지정 Teams 앱 제출·승인](https://learn.microsoft.com/en-us/microsoftteams/submit-approve-custom-apps), [조직 사용자 지정 앱 관리](https://learn.microsoft.com/en-us/microsoftteams/teams-custom-app-policies-and-settings)

## 사전 확인이 필요한 값

예시값을 실제 값처럼 넣지 않는다. 다음이 정해지지 않으면 패키지 확정과 신청을 진행할 수 없다.

- 앱의 실제 서비스 도메인과 정적 탭의 HTTPS `contentUrl`
- 실제 `websiteUrl`, `privacyUrl`, `termsOfUseUrl`
- 매니페스트 ID가 현재 사용 중인 Entra/Bot 등록 App ID와 일치하는지
- 기존에 같은 앱이 테넌트에 등록된 적 있는지(첫 제출인지 업데이트인지; 버전 결정에 필요)
- 신청할 테넌트와 제출자 계정의 앱 제출 권한

## 완료 기준

- 예시 도메인과 미완성 URL이 매니페스트에 남아 있지 않다.
- 앱 ID, 봇 등록 정보, 표시 이름, 권한 및 설치 범위가 서로 일치한다.
- 아이콘 파일이 매니페스트 경로와 일치하고 크기·형식 검증을 통과한다.
- 생성된 ZIP의 루트에 매니페스트와 두 아이콘이 있고, ZIP 내부 매니페스트가 최종 원본과 동일하다.
- 승인 신청이 조직 Teams 관리 센터에 접수되어 요청 상태를 확인할 수 있다.
- 관리자 승인 전에는 “등록 완료” 또는 “배포 완료”로 보고하지 않는다.

## 데이터 변경

없음. 이 작업에서 SQLite DB, 팀 설정 JSON, 명단, 기존 팀 데이터를 읽거나 변경하지 않는다. Teams 조직 앱 카탈로그에 새 앱 제출이 발생하는 시점은 별도의 외부 변경이며, 이 설계안 승인 후 진행한다.

## 결정 기록

- 제안: 공개 AppSource 게시가 아니라 조직 내부 앱 카탈로그 승인 신청을 대상으로 한다. 앱 설명에 “사내용”으로 기재되어 있고 요청이 “등록 신청”이므로 이 경로가 현재 의도에 가장 가깝다.
- 제안: 기존 앱 ID와 봇 등록을 재사용한다. 실제 일치 여부 확인 전까지 새 ID나 자격 증명을 만들지 않는다.
- 제안: ZIP은 기존 파일을 그대로 쓰지 않고, 확정된 원본 매니페스트로 다시 생성한다. 현재 ZIP에는 원본 매니페스트의 정적 탭이 반영되어 있지 않다.
- 미결: 실제 도메인 및 정책 URL, 첫 등록/업데이트 여부, 제출 권한.

## 검증 지도

설계 단계이므로 파일·패키지 생성, Teams 업로드, 앱 등록 신청은 수행하지 않았다.

승인 후 다음을 확인한다.

| 기준 | 검증 방법 |
| --- | --- |
| 매니페스트 구조 | 공개 Teams manifest schema로 JSON 검증 |
| 링크·ID·권한 | 실제 서비스 URL 응답과 기존 앱 등록 정보 대조. 권한은 제품에 필요한 최소 범위인지 검토 |
| 아이콘 | PNG 파일 형식·크기·투명 배경과 매니페스트 경로 확인 |
| ZIP 일관성 | ZIP 루트 파일 목록 및 내부 매니페스트와 최종 원본의 일치 확인 |
| 신청 접수 | Teams 제출 확인 화면 또는 관리 센터의 접수·검토 상태 기록 |
| 실제 동작 | 관리자 승인 뒤 Teams 설치 및 봇·정적 탭 실제 화면 확인. 확인 전까지 미검증으로 보고 |
